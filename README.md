# Overleaf Sync

把 Overleaf / ShareLaTeX 项目**双向同步**到本地文件夹的 VS Code 扩展：

- **手动模式（默认）**：点击「推送」把本地修改同步到服务器，点击「拉取」把服务器内容同步到本地；
- **自动模式**：本地保存即推送到 Overleaf，网页端修改实时写回本地，可随时切换；
- 文件的新建、删除、重命名、移动双向同步
- 同时支持官方 `overleaf.com`（Cookie 登录）与自建 ShareLaTeX / Overleaf CE（账号密码登录）

实现原理参考 [overleaf-workshop/Overleaf-Workshop](https://github.com/overleaf-workshop/Overleaf-Workshop)：REST API 负责登录与文件结构操作，Socket.IO（0.9.x 老协议）负责文档内容的 OT 增量同步。

## 安装

```bash
npm install
npm run package   # 生成 overleaf-sync-0.1.0.vsix
```

然后在 VS Code 中：`Extensions` 面板 → `...` → `Install from VSIX…` 选择生成的 vsix 文件。

## 使用方法

### 1. 添加服务器并登录

在资源管理器侧栏找到 **Overleaf Sync** 面板，点击 `+` 添加服务器（默认 `https://www.overleaf.com`）。

推荐使用 **Cookie 登录**（overleaf.com 有验证码/SSO，账号密码登录通常不可用）：

1. 在已登录 Overleaf 的浏览器中按 `F12` 打开开发者工具，切换到 **Network** 标签页；
2. 地址栏访问 Overleaf 主页（如 `https://www.overleaf.com/project`）；
3. 在请求列表中筛选 `/project`，选中该请求；
4. 在 **Request Headers** 中找到 `Cookie`，复制其中 `overleaf_session2=...`（自建服务器为 `sharelatex.sid=...`）这一段；
5. 粘贴到扩展的登录输入框中。

自建服务器也可以选择 **账号密码登录**。

### 2. 同步项目到本地

- 展开服务器节点查看项目列表；
- 点击项目（或右键 → `同步到本地文件夹…`），选择一个本地目录；
- 扩展会把项目完整下载到该目录，并生成 `.overleaf-sync.json` 记录同步状态。

### 3. 同步模式

每个项目可以选择两种同步模式（项目右键 → `切换同步模式`，选择会保存在 `.overleaf-sync.json` 中）：

- **手动模式（默认）**：两端改动都不会自动同步，通过按钮/命令手动同步：
  - **推送（本地 → 远端）**：本地优先——本地新建/删除的文件同步到远端，文档内容以本地版本覆盖远端；
  - **拉取（远端 → 本地）**：远端优先——放弃本地未推送的改动，文件结构与文档内容全部以远端为准。
- **自动模式**：在本地目录中编辑 `.tex` 等文本文件并**保存**，改动会实时推送到 Overleaf；网页端编辑会在约 1 秒内写回本地；两端的文件结构变更（新建/删除/重命名/移动）都会实时镜像到对端。

新建会话的默认模式可在设置 `overleaf-sync.defaultSyncMode` 中修改（默认 `manual`）。

在手动模式下，同步中的项目节点上会显示内联的「推送」↑ 和「拉取」↓ 按钮。

### 4. 忽略文件

在项目同步目录中创建 `.overleafignore` 文件，语法与 `.gitignore` 完全一致：

```
# 注释
node_modules/
*.tmp
build/
!build/keep.tex
doc/**/*.pdf
```

- `#` 开头为注释，空行忽略；
- `*` 匹配任意字符（不含 `/`），`**` 可跨目录匹配，`?` 匹配单个字符；
- 行首 `/` 表示从项目根目录开始匹配；不含 `/` 的规则按任意层级的文件名匹配；
- 行尾 `/` 表示只匹配目录；
- `!` 前缀表示取反（重新包含被忽略的路径），规则按顺序匹配、最后一条命中生效。

说明：

- 忽略规则只作用于**本地 → 远端**方向：被忽略的文件/目录不会推送到 Overleaf；
- 与 git 一样，**已经在同步中的文件不受忽略规则影响**（仍正常双向同步），规则只影响未同步的新文件；
- 远端 → 本地的下载不受忽略规则影响，避免远端改动造成本地数据丢失；
- `.git`、`.overleaf-sync.json` 默认始终忽略；`.overleafignore` 本身也不会被上传（可用 `!.overleafignore` 取反）；
- 修改 `.overleafignore` 后**立即生效**，无需重启同步。

### 5. 命令

命令面板（`Ctrl+Shift+P`）中以 `Overleaf Sync:` 开头：

| 命令 | 说明 |
|---|---|
| 添加服务器 / 登录 / 登出 / 移除服务器 | 服务器管理 |
| 同步到本地文件夹… | 选择项目并开始同步 |
| 停止同步 | 停止某个项目的同步会话 |
| 推送（本地 → 远端） | 本地优先：推送本地的新建/删除与文档内容到远端 |
| 拉取（远端 → 本地） | 远端优先：放弃本地未推送改动，全部以远端为准 |
| 切换同步模式 | 在手动 / 自动模式之间切换 |
| 打开日志 | 查看同步日志 |

状态栏会显示进行中的同步会话数量；断线时会自动重连并对齐状态。

## 冲突策略

- 手动模式推送时若远端也有修改，以**本地版本**覆盖远端；拉取时一律以**远端版本**覆盖本地；
- 自动模式下文档内容基于 OT 版本号同步；版本掉队时自动重新拉取该文档全量内容；
- 恢复同步/重连时（自动模式）：若远端版本未变而本地内容不同 → 推送本地离线修改；若远端已变且本地也不同 → **远端优先**覆盖本地，并弹出提示；
- 本地与远端同时编辑同一文档时，后到的改动以远端为准（建议避免两端同时编辑）。

## 已知限制

- **本地重命名/移动文件**在远端表现为"删除 + 新建"（文件内容会保留，但 Overleaf 侧该文件的编辑历史关联会断开）；
- 本地修改**二进制文件**（图片、PDF 等）会先在远端删除再重新上传；手动模式下本地对二进制文件的修改无法被检测，推送不会包含这类改动；
- 只同步保存到磁盘的内容；编辑器中未保存的改动不会推送；
- 不做编译与 PDF 预览——本地编译请配合 [LaTeX-Workshop](https://github.com/James-Yu/LaTeX-Workshop)。

## 手动测试清单

1. Cookie 登录 `overleaf.com`，项目列表正常显示；
2. 同步一个项目到空目录：所有 `.tex`/`.bib` 文档与图片等附件完整落盘；
3. 本地修改 `main.tex` 保存 → 网页端刷新可见改动；
4. 网页端修改文档 → 本地文件约 1 秒内更新；
5. 本地新建 `sections/intro.tex` → 远端出现对应文件夹与文档；
6. 网页端新建/重命名/删除文件 → 本地同步变化；
6.5. 创建 `.overleafignore` 写入 `node_modules/` 与 `*.tmp` → 新建 `node_modules/x.js`、`a.tmp` 不上传，`b.tex` 正常上传；修改 `.overleafignore` 去掉 `*.tmp` 后立即新建 `c.tmp` 可上传；
7. 关闭并重开 VS Code（工作区包含同步目录）→ 同步自动恢复；
8. 断网后再恢复 → 自动重连且内容对齐；
9. 手动模式（默认）：本地修改保存 → 远端不变化，点「推送」后远端更新；网页端修改 → 本地不变化，点「拉取」后本地更新；
10. 切换到自动模式 → 本地保存实时推送、网页端修改实时写回；切回手动模式 → 实时同步停止，且重开 VS Code 后模式保持。

## 开发

```bash
npm install        # 安装依赖并自动应用 socket.io-client 补丁（patch-package）
npm run typecheck  # TypeScript 类型检查
npm run compile    # esbuild 打包到 dist/extension.js
npm run watch      # 监听构建
```

调试：在 VS Code 中打开本目录，按 `F5` 启动 Extension Development Host（需自行添加 `.vscode/launch.json`）。
